feat: support the with modifier for input override

Policies can now exercise one rule against several inputs without
recompiling, which is what makes a policy self-testable:

    allows_read if { allow with input as {"action": "read"} }

- parser: statement-level modifiers, plus a top-level parse_query so
  Policy::query accepts "allow with input as {...}" too
- eval: the replacement document is evaluated in the enclosing scope and
  the expression runs in a child environment; bindings do not leak out
- only `with input as ...` is accepted; `with data.x as ...` and chained
  modifiers are compile errors, not silent misbehaviour
